1. 작품은 무엇으로 실행되는가

Terra Incognita는 브라우저에서 실행되는 실시간 3D 웹 작품이다.
주 실행 경로는 Three.js의 WebGPURenderer와 WebGPU이며, 별도의 Unity 또는
Unreal 실행 파일을 요구하지 않는다. 지형·기체·임무·관측·사운드·기록을
JavaScript 모듈들이 연결한다. 전시용 빌드는 하나의 자체 포함 HTML로 생성한다.


2. 사용하는 언어와 표현 방식

HTML
    캔버스, 시작 화면, 설계도 영역, 조작 버튼, 기록 페이지의 문서 구조를 정의한다.

CSS
    화면 배치, 안전 영역, 반응형 크기, 타이포그래피, 녹색 CRT 화면 처리,
    오버레이와 전환을 정의한다. visualViewport와 함께 기기 회전·주소창 변화에 대응한다.

JavaScript / ES Modules
    작품의 주 작성 언어다. 상태 전환, 자율 항로, 수동 입력, CPU 지형 표본,
    기체 관절, 임무 판정, 카메라, 음향 및 기록 저장을 담당한다.

TSL / Three.js Shading Language
    JavaScript에서 셰이더 계산 그래프를 작성하는 Three.js의 방식이다.
    지형 재질, 조명, 상대론적 장의 시각화, 컴퓨트 필드와 후처리 등을 기술한다.
    이 작품의 주 셰이더 소스는 독립된 WGSL 파일을 직접 작성하는 형태가 아니라
    TSL 노드로 구성된다. WebGPU 실행에서는 Three.js가 WGSL로 변환한다.
    GLSL / WebGL 경로는 라이브러리와 일부 모델 미리보기의 대체 렌더링에 사용되며,
    작품 전체를 WebGL로 대체 실행한다는 뜻은 아니다.

Python
    보조 제작·운영 도구에 사용한다. 예를 들어 로컬 개발 HTTP 서버와 일부 전시
    문서 제작 도구가 해당한다. 관람 중 3D 장면은 Python으로 실행되지 않는다.


3. 주요 라이브러리와 개발 도구

저장소 package.json 기준이며, 브라우저의 최신 지원 버전을 뜻하지 않는다.

Three.js 0.185.1
    장면 그래프, 카메라, 메시, 기하, 행렬, 재질과 WebGPU 렌더러를 제공한다.
    기체 모델은 절차적으로 생성한 기하와 부품 그룹으로 구성된다.
    작품 전용 engine/ 모듈이 그 위에 주행·임무·환경 시스템을 구현한다.

Anime.js 4.5.0
    제목·수신기 전환·완성 등록 장면의 DOM 애니메이션에 사용한다.
    로버 접지나 GPU 지형 시뮬레이션의 계산 엔진은 아니다.

Node.js + npm
    의존성 관리와 빌드·검증 스크립트를 실행하는 개발 환경이다.
    전시용 HTML을 관람하는 기기에 Node.js를 설치할 필요는 없다.

esbuild 0.25.12
    ES 모듈과 의존성을 묶어 전시용 자체 포함 HTML을 생성한다.
    코드·폰트·필요 리소스를 빌드에 포함해 외부 CDN 의존성을 줄인다.

Playwright 1.62.0
    브라우저 초기화, 화면 진입, 조작, 기체 모델, 설계도, 임무 시퀀스를 자동 검증한다.
    모바일 크기·터치·동작 줄이기 설정을 모사할 수 있지만 실제 iPad의 Safari,
    기울기 센서, 열 제한, 터치 하드웨어 검증을 대신하지는 않는다.


4. 브라우저 API의 역할

WebGPU
    GPU 렌더링과 컴퓨트 작업을 수행한다. 스토리지 버퍼를 이용하는 필드와
    대량의 시각 요소를 갱신한다. navigator.gpu의 존재뿐 아니라 어댑터와 필요한
    한계값을 검사한다. 주 작품은 요구 조건을 만족하지 않으면 실행을 중단한다.

Canvas 2D
    설계도 투영, 미니맵 및 일부 계기·기록 화면의 2D 그리기에 사용한다.
    설계도는 로버와 착륙선의 실제 메시에서 모서리를 추출해 투영한다.
    성능 등급에 따라 선 수를 줄인다. 이는 CAD 제작도나 공학 인증 도면은 아니다.

Web Audio API
    오실레이터, 노이즈 버퍼, 필터와 게인을 조합해 음향을 생성한다.
    임무·이동 상태에 맞춰 음향을 조절하며, 브라우저 정책에 따라 사용자 제스처가
    있어야 오디오가 활성화될 수 있다. M 또는 화면 사운드 버튼으로 제어한다.

Pointer Events / DeviceOrientation
    마우스·터치 드래그와 기기 기울기를 입력받는다. 센서는 권한과 보안 컨텍스트를
    요구할 수 있다. 사용할 수 없을 때 드래그 조향 경로를 제공한다.

requestAnimationFrame / Page Lifecycle / visualViewport
    프레임 갱신, 화면 크기 변화, 탭 숨김·복귀와 재진입을 처리한다.
    동작 줄이기 설정에서는 깜박임·잔상을 줄이면서 설계도 스캔의 왕복은 유지한다.

sessionStorage
    임무 기억, FIELD ARCHIVE와 일부 관람 상태를 현재 탭의 세션에 저장한다.
    서버 데이터베이스나 클라우드 계정에 영구 보관하는 구조는 아니다.
    브라우저의 세션 종료·저장소 정책에 따라 기록이 사라질 수 있다.


5. 계산에서 화면으로 이어지는 과정

입력
    시간, 지형 표본, 자율 항로, 키보드·터치·기울기, 누적 여정
→ 계산
    CPU 접지·조향·관절 계산, GPU 필드 계산, 관측 거리와 유지 시간 판정
→ 상태
    로버 위치, 기체 자세, 복원 단계, 원료 확정, 수분 확인, 지질 기억
→ 공간·시간 배치
    행성별 높이장, 관측 위치, 카메라 샷, 격납과 비행의 단계
→ 출력
    WebGPU 장면, Canvas 2D 설계도·지도, HTML 계기, Web Audio 음향
→ 기록
    확정된 물질·수분과 이동·체류 기록이 다음 행성의 기억장에 반영됨

행성 1은 구조 4종과 원료 2종을, 행성 2는 세 차례의 수분 관측을 다룬다.
행성 3은 이 기록과 여정에서 계산된 세 결절을 정렬한다. 수치 모델을 제거하면
결절의 배치·위상·관측 시간이 달라지는 작품의 구조도 사라진다.


6. 기체와 설계도

로버
    8개 접지점은 CPU 지형 표본으로 계산한다. 두 고정 길이 링크의 기하학적 해와
    겹치는 신축 댐퍼가 각 바퀴의 높이를 따른다. 차체·태양전지·광학 마스트는
    기존 기체의 구성을 유지한다.

착륙선
    여섯 다리의 상부 링크는 길이를 유지한다. 하부 3단 신축부는 지형에 필요한
    도달 거리와 착륙 압축을 맡는다. 발판은 지형 기울기를 표본화하되 경사각을
    제한한다. 격납 통로에는 바퀴 유도면과 네 고정부가 있다.

설계도
    별도 모델 파일을 복제해 유지하지 않는다. 현재 기체 메시의 모서리와 배치
    변환에서 선을 추출하며 복원 여부와 관계없이 전체 구조를 보여 준다.
    이때 임무의 복원 상태를 변경하지 않는다. 정지된 도면은 촬영 당시 자세이며,
    실시간 주행 중인 기체를 매 프레임 추적하는 창은 아니다.


7. 성능 정책

HIGH / MID / LOW를 사용한다. 렌더 해상도, DPR 상한, 필드·기하·입자 밀도,
후처리와 갱신 주기를 조정한다. 터치 단말은 LOW를 기본으로 선택한다.
따라서 고성능 iPad도 현재 입력 분류에서는 LOW 경로로 들어갈 수 있다.
실제 프레임 비용을 관찰하는 적응형 품질 처리도 사용한다.

새 기체 관절의 원주 분할 수와 설계도 선 수는 등급에 따라 줄이지만,
바퀴 수·다리 수·관절의 길이·임무 순서·격납 동작은 유지한다.


8. 소스와 실행 산출물

수정 기준
    works/terra_incognita/main.js              작품 시스템 연결과 프레임 순서
    works/terra_incognita/dev.html             작품 HTML / CSS 원본
    works/terra_incognita/spec.js              행성·수분 후보 설정
    works/terra_incognita/surface.js           GPU 지형 / 재질
    works/terra_incognita/surface.cpu.js       CPU 지형 표본
    works/terra_incognita/opening-blueprints.js 설계도 추출 / 스캔 / 화면
    engine/vehicle/                           로버·착륙선·관절·전력
    engine/core/                              렌더러·입력·카메라·임무·기록·음향
    engine/world/, engine/tsl/, engine/cpu/     환경과 GPU / CPU 계산

전시용 생성 파일
    index.html
    works/terra_incognita/index.html
    dist/TERRA_INCOGNITA.html

위 세 전시 파일은 npm run build로 다시 생성한다. 생성본만 직접 고치면 다음
빌드에서 사라지므로 원본 모듈을 수정한다. FIELD ARCHIVE도 빌드 과정에서 생성된다.
공개 배포에는 HTTPS를 사용하고, 전시장 오프라인 실행은 사용할 브라우저와 GPU에서
사전에 확인한다. 배포본은 외부 폰트·CDN을 가져오지 않아도 되지만 WebGPU 실행
권한이나 센서 보안 정책을 우회하지는 않는다.


9. 정확성의 범위

기하학적 계산
    좌표 변환, 메시 투영, 관절 연결점과 길이 계산은 코드의 수학적 규칙을 따른다.

수치 근사
    지형 접촉, 주행, 신축 다리, GPU 필드와 관측 시간은 실시간 실행에 맞춘 근사다.
    완전한 강체 물리, 응력 해석, 실제 우주선 기체 검증을 수행하지 않는다.

예술적 해석
    상대론적 장을 지형으로 바꾸는 비례, 물질·수분 설정값, 관측이 구조 복원과
    지질 기억으로 변하는 규칙은 작품의 해석이다. 관람자의 실제 분광 센서나
    카메라로 화학 성분을 측정하는 시스템이 아니다.
